# 智能柜型推荐 C# 后端 — 服务首页与错误页交付说明

## 你遇到的问题，根因有两个

| # | 原因 | 说明 |
|---|------|------|
| 1 | **根路径没有页面** | 之前只映射了 `/api/quotation/recommend`，访问 `http://localhost:5099` 没有任何内容可显示 |
| 2 | **残留进程占用端口** | 上次的服务进程（PID 17132）没退出，锁定了 exe 且占着 5099 端口，新实例启动失败 → 浏览器报"无法访问此页面" |

两个都已解决。

## 本次新增

### 1. 服务首页 `GET /`
访问 `http://localhost:5099` 现在会看到一个完整的服务面板：
- 顶部渐变卡：运行状态徽章 + 当前生效配置（汇率 7.2 / 盈亏平衡点 15 CBM / 默认档 F001）
- 可用接口清单
- **在线测试控制台**：直接填厂址/起运港/目的港/体积/重量，点按钮就调推荐接口，结果以表格呈现，推荐方案高亮，示例价/默认档/超重自动打标签

### 2. 统一错误页
| 状态码 | 场景 |
|--------|------|
| 404 | 页面不存在 |
| 405 | 请求方法不允许 |
| 415 | 内容类型不支持 |
| 500 | 服务器内部错误（生产环境不泄露堆栈） |

页面含大号状态码、原因说明、请求地址、返回首页按钮、可用接口清单。

### 3. 内容协商（关键设计）
同一个错误，**浏览器看到美观页面，程序拿到结构化 JSON**，互不干扰：
```
Accept: text/html        → HTML 错误页
Accept: application/json → {"status":404,"error":"页面不存在",...}
```

### 4. 固定端口 + 自动开浏览器
新增 `Properties/launchSettings.json`，以后直接 `dotnet run` 就固定 5099 端口并自动打开首页，不会再出现端口不确定的问题。

### 5. 健康检查与自检端点
- `GET /health` — 返回服务状态
- `GET /dev/throw` — 仅开发环境暴露，用于验证 500 页面（生产自动 404）

## 怎么用

```bash
cd FreightRecommend.Api
dotnet run
```

浏览器会自动打开 http://localhost:5099

**如果还是打不开**，先清残留进程：
```powershell
Get-Process FreightRecommend.Api | Stop-Process -Force
```
